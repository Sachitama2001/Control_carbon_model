# 数式から階層的に理解するモデル閲覧資料：設計・実装計画

作成：2026-09-25。状態：提案。今回は計画書のみを作成し、モデル・ワークブック・実験結果は変更しない。

## 1. 達成したいこと

入口には一つの式だけを置く。

\[
\frac{dx}{dt}=B\mu(t)+A\xi(t)Kx.
\]

読者は、知りたい記号を選び、その意味、構成要素、過程、仮定、具体式、原典へと、自分の必要な深さまで進める。途中で止めても、その深さで意味が通じる資料を作る。

たとえば「xとは何か」から炭素・窒素・水の貯留へ進み、炭素の植物・土壌、植物の葉・幹・根・NSCへ進む。「Bとは何か」から配分を読み、固定配分の説明、状態に応じた配分、目標LAIと実LAIの差、ソースの条件分岐へ進む。どの画面でも元の式と現在位置を見失わない。

成果の基準は、行列の全要素を掲載したことではなく、**読者が「何が蓄えられ、何で変化し、どの仮定がその変化を決めるか」を説明できること**とする。数値を入力しなくても使えることを必須とする。

## 2. 既存成果物とのずれと、引き継ぐ資産

既存の `visit_workbook.py` は、状態・流量・式の依存関係を保持し、`visit_workbook_export.py` がExcel数式と計算済み値を生成している。出典、日次更新順序、収支、native照合がある。これは再利用価値が高い。

一方、現在の案内は、大きな行列、変数辞書、過程シート、出典シートを読者が往復する設計である。計算上の分解は充実しているが、読者の疑問に沿った説明の階層は別途必要になっている。ExcelのシートをHTMLページへそのまま移しても、この問題は残る。

新しく設計するのは、既存の計算・検証情報に付ける**説明の構造と閲覧経路**である。計算グラフから依存関係は抽出できるが、「この式は何のためにあるか」「最初に何を省略して説明するか」は明示的に執筆する。

## 3. 「深掘り」を三種類に分ける

見た目の操作は統一してよいが、何をしたかを短いラベルで区別する。

| 操作 | 意味 | 例 | 数値・モデルへの影響 |
|---|---|---|---|
| 内訳を開く | 同じモデルに含まれる要素を表示 | 植物炭素→葉・幹・根・NSC | 元の状態・計算は変わらない |
| 仕組みを開く | 同じ過程の説明から具体式・分岐へ進む | 動的配分→目標LAIとの差→分岐式 | 元の式は変わらない |
| 仮定を比べる | 異なる定式化・モデルを比較 | 固定配分と動的配分、NSCなしとあり | 別モデル／近似であることを表示 |

固定配分は動的配分の「省略表示」とは限らない。動的配分を基準状態で固定した近似であれば、その基準状態と有効範囲を明示する。別の理論モデルであれば、単純・詳細という優劣ではなく異なる仮定として並べる。

同様に、植物を一つの箱で表示することは、葉・幹・根を一状態へ縮約した閉じたODEが得られたことを意味しない。この違いを、詳細画面だけに隠さず、操作箇所に「表示の集約」「近似モデル」と表示する。

## 4. 説明の深さ

全体を一括で詳細化するスライダーは初版では設けない。xを深く開きながらBは概略のまま、といった読み方を可能にする。

| 深さ | 読者の問い | 主に見せる内容 |
|---|---|---|
| 0：全体 | 何の変化を表す式か | 一つの式、入力・移行・損失の一文説明 |
| 1：意味 | この記号は何か | 日本語の意味、簡単な箱と矢印 |
| 2：構成 | 何からできているか | 状態群、流量、配分先、代表的な過程 |
| 3：仕組み | 何に依存して変わるか | 短い式、依存変数、仮定、主要な分岐 |
| 4：実装・根拠 | 実際にはどう計算するか | 完全な式、単位、更新順序、ソース、検証範囲 |

各項目の冒頭には、前の階層だけを読んだ人にも分かる一文を置く。コード、長い係数表、原典の問題点は必要な箇所で開く。未実装や別モデルという、解釈を変える情報は浅い階層でも表示する。

## 5. xからの閲覧設計

入口では、xを「モデルが記憶する貯留量」と説明する。炭素・窒素・水の横に、必要に応じて「履歴・補助状態」を分けて表示する。

```text
x：状態
├─ 炭素
│  ├─ 植物
│  │  └─ 選択モデルに実在する器官・貯蔵プール
│  └─ 土壌
│     └─ 選択モデルに実在するリター・腐植等のプール
├─ 窒素
│  ├─ 植物
│  └─ 土壌
├─ 水
│  └─ 選択モデルに実在する雪・土壌水・植物水等
└─ 履歴・補助状態
   └─ 前日値、フェノロジー記憶等
```

この図は分類の骨格であり、全モデルがすべての箱を持つという意味ではない。

### 器官と物質の分類

「葉・幹・根」は器官、「構造炭素・NSC」は炭素の形態であり、同じ一本の木に無理に固定しない。標準経路は物質→植物／土壌→器官とし、「器官で見る」「貯蔵炭素を見る」で同じ状態を別の分類から探せるようにする。状態IDは共通にし、表示を増やしても貯留量を二重計上しない。

たとえば旧VISITの単一NSC貯蔵を、温度–NSC理論モデルの器官別NSCに見せかけて分割しない。器官別NSCを見たい場合は「別モデルでの表現」へ進む。

### 微生物など、希望する箱がない場合

選択モデルに独立した微生物状態があるかを台帳で確認する。ない場合は「独立した状態としては表現されていない」と示し、対応する分解過程・省略仮定へ案内する。土壌の活性プールを根拠なく微生物炭素と命名しない。詳細を開く操作だけで新しい状態を作らない。

### 集約時の約束

同じ物質・同じ面積基準・互いに重ならない状態の合計だけを集約値にする。C、N、水を足した「全状態総量」は表示しない。DOC濃度や履歴も貯留量へ無条件に加えない。

集約を数学的に述べる場合は y=P x とし、dy/dt=P f(x,u) までは厳密である。しかし、これをyだけで閉じるには別途条件または近似が必要である。初版は表示の集約に限定する。

## 6. Bとallocationからの閲覧設計

Bの短い説明は「入力・有効流量を、どの箱へどれだけ配るかを対応付ける」とする。モデルによって役割が違うため、Bを常に「GPPの固定配分率」と定義しない。

標準の説明経路は次のようにする。

```text
B：どこへ配るか
  → 植物への炭素配分
    → 固定割合ならどう表すか（説明用の簡単な例）
    → 仮定を比べる：状態に応じて変える場合
      → 実LAIと目標LAIの差
        → 目標LAIを決める光獲得と維持・更新コスト
        → 配分率を決める条件分岐
          → 選択したVISITソースの実装と更新順序
```

説明用の固定配分例は、b=(b_L,b_S,b_R)、b_i≥0、Σb_i=1とする。数値を置く場合は「説明用」と明示し、TKYの採用値と混ぜない。

動的配分では、b=b(x,T,履歴,…)と書き、何に依存するかを短い依存関係図で見せる。「最適LAI」は選択した式と仮定の下での目標であり、森林一般の最適性と断定しない。目標値の計算と、その目標へ近づく実際の流量を別カードにする。

VISITの区分式については、直感的な「不足が大きいほど葉へ多く配る」という説明で済ませず、境界の扱い、上限が適用される分岐、EPPの符号、日次計算順を最深層で示す。図示は原式を確認してから作る。

既存ブックのμはGPPそのものではなく、正の器官純入力や残差を含む有効流量である。またNSCからの成長は系内移行である。したがって、説明上の「allocation」から、実際の分解ではBμとAξKのどちらに現れるかを追えるようにする。Bの一画面だけにすべてを押し込めない。

## 7. 他の記号と、式の意味を保つ方法

| 入口 | 最初の説明 | 深掘りの例 |
|---|---|---|
| μ | 入力・有効流量の大きさ | GPP、降水、窒素沈着、内部流量・残差との区別 |
| A | どこからどこへ移り、どこから失われるか | turnover→リター、呼吸、供給側と受取側 |
| ξ | 環境や状態で速度がどう変わるか | 温度、水分、土性、原典の補正式 |
| K | 基準となる速度・規格化 | turnover、分解、単位、便宜的規格化 |
| dx/dt | 何がどれだけ増減するか | 各箱の収支、総炭素・総窒素・総水収支 |

### 時間表現

最初の式は概念の入口として保持する。モデルを選ぶと直下に「連続時間モデル」または「日次更新モデル」を常時表示する。native日次版は、その場で

\[
\Delta x/\Delta t=B\mu+A\xi Kx,
\qquad x_{n+1}=x_n+\Delta t\,f_\Delta
\]

という実際の時間表現へ切り替える。xに含めていない履歴hが必要なら、その依存も表示する。日次写像の増分を厳密なODEだとは説明しない。

### 状態依存と分解の非一意性

簡略表記のξ(t)などは、外から与えられる時刻関数だけを意味するとは限らない。詳細を開くとB(x,h,u)、μ(x,h,u)、A(x,h,u)、ξ(x,h,u)を表示する。AξKとヤコビアンの違いは解析へのリンクで説明する。

この行列分解は一意ではないため、分解規約をモデルごとに固定する。表示階層を開閉しても、BとAの間で勝手に項を移さない。

### 水と異種の物質

水輸送では必要に応じて「接続行列×流量」の形を開く。水ポテンシャル差による逆流や有効残差まで、正の炭素配分率に見せかけない。状態ベクトルは異なる単位の成分を持てるが、各行の入出力は単位が一致する必要がある。C・N・水の関連は、物質移動と係数への依存を別の矢印で示す。

## 8. 画面と操作

初期画面は「式」「現在のモデル」「一文の説明」を中心にする。詳細を開いたときだけ、左に閲覧経路、中央に説明、右に選択項目の詳細を配置する。

```text
モデル：旧VISIT / TKY / 選択した日次経路      表示：概要

               Δx/Δt = [B] [μ] + [A] [ξ] [K] [x]

場所：式 → B → 植物への炭素配分 → 目標LAI

〔配分先の箱と矢印〕        〔目標LAI〕
 葉   幹   根                光獲得と葉のコストから決める目標
                            [仕組みを開く] [仮定を比べる]

 [ひとつ戻る] [全体へ]       [具体式] [原典と検証]
```

操作仕様：

- ホバーまたはキーボードフォーカス：意味と単位を短く表示する。
- クリック／Enter／タップ：詳細を固定して開く。説明の必須部分をホバーだけに置かない。
- パンくずと戻る：開く前の位置と展開状態に戻る。全体の式を常に確認できる。
- 「仮定を比べる」：二つの説明を横に並べ、変わる状態・式・仮定・適用範囲を示す。モデルを黙って切り替えない。
- 「この説明へのリンク」：モデルIDと項目IDを含むURLのfragmentを保存できる。
- 「微生物」「NSC」「allocation」などの別名検索：該当項目、別モデルの項目、または未表現という説明へ到達できる。
- 色だけに依存せず、矢印の種類・凡例・ラベルでも物質移動と依存関係を区別する。

全体の巨大な依存グラフは初期表示にしない。選択項目とその直接の依存先を表示し、さらに先を開けるようにする。

数値を見る場合は「例を表示」を明示的に選ぶ。基準日、設定、値の出典を併記し、概念説明に数値を必須としない。初版では入力編集や新たなシミュレーションを提供しない。

## 10. 説明データと計算データの関係

分類は木として見せるが、実体は関連を持つデータとして保存する。LAIは光合成にも配分にも使われるため、説明をコピーせず同じ項目を参照する。

各項目の最低限の情報：

| 項目 | 内容 |
|---|---|
| ID・モデルID | 版が変わっても追跡できる識別子 |
| 名前・別名 | 日本語、数式記号、NSC等の検索語 |
| 種別 | 状態、状態群、流量、過程、パラメータ、履歴、モデル比較 |
| 説明 | 一文要約、構成、仕組み、完全な定義 |
| 関係 | 内訳、依存先、流入先、流出先、別モデルの対応項目 |
| 単位・集約規則 | 面積基準、合計可能な範囲、重複の扱い |
| 適用範囲 | モデル、経路、分岐、連続／離散、近似レベル |
| 根拠 | 原典repo・commit・path・function、更新順、検証参照 |
| 実装への対応 | 既存State／Flux／NodeのID。対応がなければ未実装と記録 |

「内訳」「依存」「物質移動」「別モデル対応」は異なる関係とする。読者には日常的な表現で見せ、内部のデータ構造名を学ばせない。

既存Graphは計算順を表すDAGである。生態系のフィードバックを説明する関係図には循環があるため、両者を同一のグラフとして扱わない。

既存の式・数値はアダプター経由で参照し、JavaScriptに生態過程を再実装しない。初版は検証済みの静的スナップショットと説明に限定する。人が執筆する要約にも対応する実装IDとモデル版を付け、式変更時に見直す説明を特定できるようにする。

配置案（以下は将来の実装予定であり、今回は作成しない）：

```text
src/control_carbon/model_explorer/  既存モデルからの抽出・検証・生成
tests/test_model_explorer_*.py      対応・収支・出典等の必要な検証
artifacts/model_explorer/           生成HTML・印刷版・manifest
```

## 11. 実装順序と各段階の完了条件

### 第1段階：説明の見取り図を確定する

最初に扱う実モデルは、既存ブックで監査済みの旧VISIT TKY日次経路とする。別に、固定配分を説明する小さな概念例を明確なラベル付きで置く。現行VISITcや温度–NSCモデルを混ぜて一つのモデルにはしない。

作るものは、記号ごとの一文説明、xの実在する分類、allocationの説明経路、表示集約とモデル比較の対応表。微生物・器官別NSC・植物水など、選択モデルにない表現を先に確認する。

完了条件：xとBについて、どこまで同じモデルの説明で、どこから別の仮定かを紙面で追える。

### 第2段階：xとBだけを最後までたどれる試作

一つの式から、状態一覧、NSC、配分、目標LAI、原典へ到達できるHTMLを作る。他の記号には短い説明だけを置く。全37状態を最初から詳細カード化する前に、望んでいた読み方に合うかを確認する。

完了条件：下記の利用場面1〜5を実際に操作できる。ローカルファイルとして開ける。クリック・キーボード・戻る・直接リンクが機能する。ここでの利用者レビューは将来の試作に対するものであり、本計画作成の前提条件ではない。

### 第3段階：既存検証情報へ接続する

State／Flux／Nodeの識別子と説明項目を対応させ、μ・A・ξ・K、物質別収支、必要な履歴へ広げる。既存の基準日例を任意表示し、集約値・流量・原典への参照を照合する。

完了条件：同じ状態が分類を変えても同一値を示す。物質別の合計が既存値と一致する。未設定・未定義・不採用をゼロと区別できる。日次版の表示式が原典の更新意味を保持する。

### 第4段階：モデル間の仮定比較

温度–NSC、温度–降水、SPACの各モデルを独立したモデルとして追加する。対応が定義できた概念だけを比較可能にする。対応しない状態や異なる境界は「対応なし」「比較には追加仮定が必要」と示す。

完了条件：モデルを変えたとき、状態数、単位、入力、時間表現、出典が一緒に変わる。固定配分から動的配分への比較が、単なる表示展開とは区別できる。

### 第5段階：保存・配布と更新手順

HTML、選んだ説明経路の印刷版、説明データ、生成元の版をまとめる。閲覧可能性と出典までの到達性をネットワークなしで確認する。外部の原典サイトへ行けなくても、必要な式・要約・commit・pathは読めるようにする。

完了条件：別の場所へ配布物をコピーしても使え、現在の展開状態・モデル・項目を復元できる。モデル更新時に生成と対応検証を再実行する手順が文書化されている。

初回の実装範囲は第1〜2段階を推奨する。全モデルの収録や入力編集は、この試作で説明の使い勝手が合うと確認してから進める。

## 12. 利用場面による受入基準

| 場面 | 読者の操作 | 合格となる状態 |
|---|---|---|
| 1. 最初の理解 | 開いて式を読む | 入力・移行・損失・貯留の意味が分かり、巨大行列を読む必要がない |
| 2. NSCを探す | x→炭素→植物→NSC | 構造炭素との違い、選択モデルでの保持方法、器官別か否かを説明できる |
| 3. 水を探す | x→水 | 選択モデルにある貯留と、別モデルにしかない貯留を判別できる |
| 4. 配分を理解する | B→炭素配分→目標LAI | 固定割合の意味と動的配分の依存関係を説明できる |
| 5. 根拠を確認する | 目標LAI→具体式→原典 | 目標値計算と配分計算を区別し、ソース関数・単位・分岐へ到達できる |
| 6. 微生物を探す | 検索または土壌を展開 | 独立状態の有無を確認でき、ない箱が捏造されていない |
| 7. 元へ戻る | 戻る／パンくず | 開く前の文脈と選択モデルを保ったまま全体へ戻れる |
| 8. 共有する | 項目リンクをコピー | 同じモデル・項目へ直接移動できる |
| 9. 集約を見る | 葉・幹・根等をまとめる | 同物質の総量を保ち、閉じた縮約モデルとは混同しない |

数式整合性・対応ID・単位・リンク切れは機械的に確認する。説明の理解しやすさは、上記の問いに利用者が自分の言葉で答えられるかで確認する。テスト件数だけを使いやすさの証拠にしない。

## 13. この提案で決めたことと残したこと

今回の提案では、式を入口とすること、段階的に開くこと、同じモデルの展開と仮定比較を区別すること、オフラインで残すこと、既存Excelを監査資料として活用することを設計の柱とした。

残る判断は、実際の試作を見たうえでの、同時に開く情報量、図と文章の比率、比較画面の配置である。これらは内容を持つx・Bの試作で判断する。数式の再計算やパラメータ探索機能は、理解のために必要だと分かった場合に別途追加する。

最初に作るべき成果物は、**一つの式からxとBを選び、「箱の意味」と「配分の理由」までたどれる小さな閲覧資料**である。
